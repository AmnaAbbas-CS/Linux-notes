# Episode 2: Files, Permissions and the System

## What I learned

| Command | What it does | Why it matters |
|---|---|---|
| `cat` | Prints a file's contents | Fastest way to read configs and logs |
| `mkdir` | Creates a folder | Organizing work |
| `cp` / `cp -r` | Copies files / folders | Backups before editing |
| `rm` | Deletes with no recycle bin | Check the name before deleting |
| `ls -l` | Shows owner and permissions | Core security skill |
| `chmod +x` | Makes a file runnable | How scripts become executable |
| `which`, `echo $PATH` | Where commands are found | PATH is a known attack target |
| `ip a` | Shows IP and interfaces | First step in network work |

## Problems I hit and how I solved them

### 1. Copied `ls` as `networkchunk` and it would not run
- **Error:** `unknown program`
- **Cause:** On Ubuntu 26.04, `ls` is a link into `coreutils`, a single program that decides
- which tool to be from the **name** it is called by. The copy was perfect but did not recognize
-  its new name.
- **Proof:** `ls -l /usr/bin/ls` and `readlink -f /usr/bin/ls` show the link.
- **Fix:** Made a tiny script that runs `ls`, then used `chmod +x`.

### 2. `cp bin` failed
- `cp` needs `-r` to copy folders.
- In `/` I got Permission denied, because normal users cannot write there.
- `/bin` is a link to `/usr/bin`, not a separate folder.

### 3. `sudo` was needed in one place but not another
- `sudo` was needed in system folders owned by `root`.
- It was not needed in my own folder, which I own. Checked with `ls -ld`.

### 4. `/etc/network/interfaces` does not exist
- Modern Ubuntu uses NetworkManager and Netplan instead of that old file.
- Used `ip a` to find my IP.

## Key takeaways
- Linux decides what I can do based on **who owns** the file.
- Tutorials are often recorded on older systems, so small differences are normal.
- Investigate why instead of guessing.
